# 👁️ فاحص (FAHES) — نموذج فرز بصري أولي تجريبي

## النشر على Vercel (المسار الأساسي)

تم إصلاح خطأ `FASTAPI_ENTRYPOINT_NOT_FOUND`: تطبيق Streamlit لا يمكن نشره مباشرة على Vercel كخادم FastAPI. لذلك أضيف مدخل FastAPI حقيقي في `app.py` وواجهة عربية سريعة في `web_ui.py`، مع إعادة استخدام محركي `triage.py` و`eye_quality.py`.

1. استورد المستودع إلى Vercel أو أعد نشر آخر تحديث على الفرع `main`.
2. اختر **Root Directory** على جذر المستودع (اتركه `./`).
3. اجعل **Framework Preset** على `Other` أو اترك الاكتشاف التلقائي لـFastAPI، ولا تضف أمرًا لتشغيل Streamlit.
4. استخدم **Build Command** و**Output Directory** بالإعدادات الافتراضية (دون تخصيص).
5. سيقرأ Vercel `pyproject.toml` الذي يحدد `app:app`، و`requirements.txt` لتثبيت FastAPI.
6. بعد نجاح النشر، افتح `/` لرؤية الواجهة، أو `/api/health` لاختبار API.

أبرز المسارات:
- `GET /`: واجهة عربية متوافقة مع الجوال، التقاط صورة أو رفعها، واستبيان أعراض.
- `GET /api/health`: حالة الخدمة.
- `POST /api/screen`: طلب `multipart/form-data` يتضمن الصورة اختياريًا، `image_type` (`external` أو `fundus`)، `symptoms` (مصفوفة JSON)، `has_diabetes`، و`age`.
- يعتمد حفظ PDF على طباعة المتصفح، ويمكن أيضًا تنزيل Markdown وFHIR تجريبي دون صور أو تشخيص.

**حدود Vercel:** الحد الأقصى لحجم طلب الوظيفة 4.5MB؛ تُضغط الصور التي تتجاوز 4MB قبل إرسالها من المتصفح، والخادم يرفض الملفات الأعلى من 4MB. قد يؤثر الضغط على مؤشرات الحدة التقنية؛ فهذه المؤشرات تجريبية وغير سريرية. لا تخزن الخدمة صورًا أو تسجلها في قاعدة بيانات.

## تشغيل Streamlit محليًا (مسار اختياري مستقل)

```bash
pip install -r requirements-streamlit.txt
streamlit run streamlit_app.py
```

تم فصل تبعيات Streamlit الثقيلة عن `requirements.txt` كي لا تزيد حزمة وظائف Vercel. يحتفظ المستودع بنسخة Streamlit القديمة للاستخدام المحلي أو على استضافة مناسبة لها.

---



تطبيق **Streamlit باللغة العربية** يتيح تصوير مقدمة العين بكاميرا الجوال أو رفع صورة قاع العين الملتقطة بملحق بصري، ثم يفصل بوضوح بين:

1. **جودة الصورة التقنية** (الإضاءة، الحدة، الدقة، الانعكاسات) — عتبات إرشادية غير معايرة سريريًا.
2. **التوجيه المبني على الأعراض** — قواعد واضحة للمواقف التي تتطلب مساعدة عاجلة أو مراجعة مختص.
3. **تقرير تجريبي** — Markdown وHTML للطباعة وFHIR R4 collection، **دون أي احتمالات مرضية مختلقة**.

> **مهم:** لا يقيس التطبيق قوة النظر، أو HbA1c، ولا يشخّص السكري أو اعتلال الشبكية. **اجتياز بوابة الجودة لا يعني أن العين سليمة**، ولا يثبت أن الملف المرفوع صورة عين أصلًا.

## تشغيل النموذج

يتطلب Python 3.11 أو نسخة متوافقة:

```bash
pip install -r requirements.txt
streamlit run streamlit_app.py
```

يمكن فتح التطبيق من الجوال عبر رابط HTTPS بعد نشر Streamlit؛ السماح للكاميرا يحتاج إذن المتصفح وبيئة آمنة. اختيار **التقاط بالكاميرا** يستخدم `st.camera_input`. الصور المرفوعة تصل إلى خادم Streamlit للمعالجة أثناء الجلسة، **وليست معالجة على الجهاز**.

### طريقة التجربة

1. اختر **مقدمة العين** إذا كنت تستخدم كاميرا الهاتف العادية، أو **قاع العين** فقط إذا كانت لديك صورة ملتقطة بأداة تصوير مناسبة.
2. التقط صورة أو ارفع JPG/PNG/WebP حتى 10MB و24MP.
3. راجع ملاحظات الإضاءة والحدة. قد تفشل صورة صحيحة أو تنجح صورة ليست للعين؛ بوابة الجودة تقنية فقط.
4. حدد الأعراض إن وُجدت واذكر تشخيص السكري السابق إن رغبت.
5. اطلع على **أولوية التوجيه**، وأنشئ تقرير HTML (يمكن فتحه ثم طباعته PDF)، أو Markdown، أو FHIR JSON.

## منطق أولوية التوجيه

| الحالة المبلّغ عنها | رسالة التطبيق | ما الذي لا يدّعيه؟ |
| --- | --- | --- |
| فقدان نظر مفاجئ / ألم شديد / ستار بصري / إصابة أو مواد كيميائية / ومضات أو عوائم جديدة | طلب تقييم عاجل دون انتظار الصورة | ليس تشخيصًا لحالة بعينها |
| تشوش متكرر أو احمرار مستمر أو أعراض ارتفاع سكر أو سكري معروف | مراجعة مختص أو رعاية أولية | لا يستنتج السكري من العين |
| لا أعراض معلنة | لا توجد أعراض إنذار مُبلّغ عنها | **لا يصرح بأن العين سليمة** |
| صورة رديئة | نصائح إعادة التصوير، مستقلة عن الحاجة العاجلة | فشل الصورة لا يحوّل الأعراض العاجلة إلى منخفضة الخطورة |

القواعد في `triage.py`. يمنح التطبيق **التوجيه المستند إلى الأعراض** أولوية على بوابة جودة الصورة؛ لذا لا تؤخر الصورة المرفوضة علاج حالة طارئة.

## هيكل المشروع

| الملف | دوره |
| --- | --- |
| `streamlit_app.py` | الواجهة العربية، التصوير المباشر، عرض الأعراض والتقرير |
| `eye_quality.py` | فحص جودة صورة تقنية تجريبية؛ لا يتعرف على أمراض |
| `triage.py` | توجيه غير تشخيصي بالأعراض والعوامل المبلّغ عنها |
| `triage_export.py` | تصدير FHIR تجريبي بلا درجات احتمال مرضي |
| `tests/test_triage.py` | اختبارات القواعد والخصوصية المنطقية والفصل بين الصورة والتشخيص |
| `fusion.py`, `fhir_export.py`, `image_checks.py` | **مكونات قديمة بحثية** محفوظة للمرجعية، ليست ضمن المسار الصحي الجديد |

## لماذا لا نستخدم نموذج CLIP القديم للتشخيص؟

كانت النسخة الأولى تُشغّل `openai/clip-vit-base-patch32` بتصنيفين لوصف صور الشبكية، ثم تعامل نتائج softmax معاملة احتمال اعتلال شبكية. **هذه ليست احتمالات مرضية معايرة، ولا توجد دراسة أداء سريري تثبتها**. كما أن حساب 60% صورة + 20% ساعة + 20% سجل هو **تصور تجريبي** لا يمثل معادلة خطر سريرية.

لهذا عُزل `fusion.py` عن الواجهة ولم يعد تنزيل تقرير FHIR من الواجهة يصدّر `RiskAssessment.probabilityDecimal`. الكود القديم متاح للاطلاع فقط، لا لإعادة استخدامه في اتخاذ قرارات على مرضى.

لإضافة نموذج حقيقي لاحقًا: اجمع بيانات مصرحًا باستخدامها، وطابق **نمط التصوير** (صور خارجية مقابل fundus)، وافصل عينات التدريب والتقييم على مستوى المرضى، واختبر الحساسية والنوعية، منحنيات المعايرة، الأداء لكل نوع كاميرا وفئة سكانية، وخطة الإحالة والمراجعة البشرية. لا تُعلن دقة أو أثرًا صحيًا قبل القياس الفعلي.

## الخصوصية والتنظيم

- لا تتضمن هذه النسخة قاعدة بيانات أو رفعًا إلى خدمات AI خارجية. ومع ذلك فإن **Streamlit يعالج الصور على الخادم**، وليس على الجهاز؛ ولذا يجب تأمين الاستضافة قبل الاستخدام خارج التجربة.
- لا تُدرج صورة العين في تقرير FHIR أو HTML. اسم المستخدم غير مطلوب، والعمر اختياري. لا يُستنتج تاريخ ميلاد مزيف من العمر.
- لا توجد حساسية أو نوعية أو معدل اكتشاف مثبت؛ ولا يجوز استخدام التطبيق لاستبعاد مرض أو توفير زيارة عيون.
- التصوير الخارجي لا يكشف الشبكية. تصوير قاع العين يتطلب أداة بصرية مناسبة.
- عند الانتقال للاستخدام السريري في المملكة: راجع حماية البيانات الشخصية ومتطلبات تنظيم البرمجيات الطبية لدى **الهيئة العامة للغذاء والدواء**، مع إشراف مختصين سريريين.
